# Native Methods models in a persistent Octave DAG controller

The Octave controller translates the existing native DAG process protocol into
`n4m.RolePipeline`. DAG-ML owns HPO, folds, nested OOF, selection, signing and
replay; the public Methods ABI owns recipes, fitted states and numerical work.
This adapter accepts already materialized numeric projections. Raw N-D encoders
and licensed MATLAB are outside this qualification.

The implementation is authored; native Octave qualification remains pending
until a real Octave 7.1+ executable with native `jsondecode`/`jsonencode` and
compiled MEX are available. The adapter checks these capabilities at startup. No mock can close
this gate.

## Controller and artifact contract

`controller:methods.octave.regression` version `1.0.0` produces RAW artifacts
with plugin `dagml.methods.octave.regression`, version `1.0.0`. Archive V2 accepts
this exact plugin and owner pair. The closed wrapper retains precisely
`schema`, `node_id`, `params_fingerprint`, `target_names`, `steps`,
`feature_names` and `states`; its schema is `dagml.methods.regression.v1`.
The content-addressed URI, size, owner and SHA-256 bind the original UTF-8 bytes.
DAG-ML revalidates the complete ordered recipe against the effective plan before
callbacks. Methods imports each opaque N4ME state and validates compatibility.

The adapter uses Octave's `jsondecode(..., 'makeValidName', false)` to retain
keys containing `:` and `.`. Cell arrays retain singleton JSON arrays; nested
numeric state arrays are split at their JSON boundaries before decoding.
The lineage seed comes from the exact native JSON token, preserving the entire
u64 range without converting it through a double. See the
[Octave JSON documentation](https://docs.octave.org/latest/JSON-data-encoding_002fdecoding.html).

Current numeric rows and OOF columns are joined by sample ID in the same ordered
namespace sequence as the R controller. Excluded fitting rows, augmented rows,
nonuniform influence, custom losses, residuals and generated views require a
specialized controller and are refused here. PREDICT checks current ordered
features, parameters, recipe and artifact owner before numerical work. A replay
adapter receives no targets and disables fitting. Hydrated states close on
release, worker close, EOF and failure cleanup.

## Prepare and execute

Build the public Methods RolePipeline MEX as documented by
`nirs4all-methods/bindings/matlab`. For this qualification use the public
`nirs4all-methods==1.2.1` runtime, ABI `2.14`, and matching released headers.
Current development headers may advertise a newer ABI and must not be mixed
with that released library. Set `DAG_ML_OCTAVE_METHODS_PATH` to the binding root;
set `DAG_ML_OCTAVE_MEX_PATH` only when its MEX package lives in another root.

Use the unchanged capture generated by
`scripts/smoke_wasm_multimodal_methods_hpo.mjs`, already used by the R gate.
It supplies the four projections, native folds, twelve samples, three proposals
and all five fitted recipes. The first recipe uses Ridge with `alpha=0.05`.
The qualification preserves every recorded proposal and compares native scores
and predictions with that captured witness, without another Ridge oracle.

```bash
DAG_ML_OCTAVE_METHODS_PATH=/path/to/nirs4all-methods/bindings/matlab \
python scripts/qualify_multimodal_methods_hpo_octave.py \
  --node-capture /path/to/unchanged-four-source-receipt.json \
  --cli /path/to/current/dag-ml-cli --octave /path/to/octave \
  --workdir /path/to/new-octave-qualification
```

This gate exercises the public native CLI and Python phase APIs, captures five
actual RAW model wrappers, writes/reads a Core `.n4a`, and replays from a fresh
Octave process with no FIT. It also requires refusal of altered trust, phase,
archive bytes, missing/aliased members, same-width feature permutations and
fitting-disabled requests, plus cleanup after an injected prediction failure.
Its receipt records source capture, runtime/MEX origins and hashes, score
comparisons, native lifecycle counts and archive identity.

## Public Python and nirs4all callers

The helper accepts phase API injection so a caller can exercise its own public
facade without moving orchestration or numerical work into Python:

```python
from pathlib import Path
import nirs4all
from scripts.qualify_multimodal_methods_hpo_octave import (
    OCTAVE_MANIFEST, OctaveWorker, check_no_fit_replay,
    prepare_octave, train_from_python_api,
)

trained = train_from_python_api(
    Path("four-source-receipt.json"), Path("/usr/bin/octave"), Path("octave-training"),
    hpo_search=nirs4all.run_host_hpo_search,
    execute_training=nirs4all.execute_training,
)
archive = Path("five-native-models.n4a")
nirs4all.write_portable_predictor_archive_v2(
    archive, archive_id="archive:octave.example", outcome=trained["outcome"],
    package=trained["package"],
)
prepared = prepare_octave(
    Path("/usr/bin/octave"), Path("."), "fresh-replay", trained["heldout"],
    trained["operators"], None,
)
with OctaveWorker(prepared) as worker:
    prediction = nirs4all.replay_portable_predictor_archive_v2(
        archive, trained["replay_request"], trained["replay_envelopes"],
        [OCTAVE_MANIFEST], worker.operator, artifact_callback=worker.artifact,
        outcome_id="outcome:octave.example", run_id="run:octave.example",
    )
    proof = check_no_fit_replay(worker, prepared)
```

Without injected functions the helper uses `dag_ml`'s public phase APIs. SDK
integration tests inject `nirs4all`'s public functions explicitly and use an
installed, isolated Python consumer for archive replay.

## Required gates

After the complete feature has passed both independent reviews, run native
Rust archive/profile regressions, the independent archive validator tests,
and real Octave protocol coverage:

```bash
DAGML_REQUIRE_OCTAVE_ROLES=1 \
NIRS4ALL_OCTAVE_ROLE_NODE_CAPTURE=/path/to/unchanged-four-source-receipt.json \
DAG_ML_OCTAVE=/path/to/octave \
python -m pytest tests/test_octave_methods_role_adapter.py
```

The required mode fails if Octave or the captured fixture is unavailable.
The manual `methods-octave-role-candidate.yml` workflow selects explicit Methods
and SDK source refs, compiles the real MEX against ABI 2.14, and consumes a
captured fixture artifact from the existing WASM candidate workflow. It runs
the matching released Methods role fixture, DAG qualification, and the SDK's
public phase and installed isolated consumer tests, retaining their evidence.
It never publishes packages. The old scalar Octave Ridge oracle remains a
separate gate.
